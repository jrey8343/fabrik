## What changed

<!-- One bullet per Ticket, each written by its own Ticket: #762 (the Coding standards), #763 (the Design session's rule), #764 (the Implementer's out-of-reach criteria), #765 (the Reviewer's Design flaw), #766 (Ticket compliance version 3), #767 (Design at high). -->

- **Every Implement run is given the Coding standards** ([#762](https://github.com/jrey8343/fabrik/issues/762)). The whole of a Product repo's `CODING_STANDARDS.md`, from the root of the checkout, now goes inline into the Implementer's prompt, under the same heading and in the same form as the Reviewer's, with nothing cut or summarised. That covers a first run, a Kept-branch start, a Retry (the Step-up included), a Touch-up, a Request-changes run, a conflict-only run and a Replay Arm's Implement run, which gets the file as the Ticket's base commit holds it. The Implement prompt tells the run to build to it in the code it writes or changes, says the Reviewer judges the pull request against the same text, and has it name older code that breaks a rule in its summary instead of fixing it. A repo with no such file gets nothing in its place, a prototype turn gets none, and `.fabrik/review.md` and the review prompt still go to the Reviewer alone. The file stays a Trust-root file that only the Operator changes.
- **A Design session holds every acceptance criterion to what a run can meet** ([#763](https://github.com/jrey8343/fabrik/issues/763)). A criterion is one check on a Ticket that a test the Required checks run, or the diff itself, shows is met, and it never asks for a Trust-root change, a GitHub write, a commit, branch or state the run isn't given, a suite or command no Required check runs, or anything only the Operator can do. The rule covers an agent brief's criteria, each Ticket's in a Spec or a split, and a Roll-in's. An async turn is now given the Required checks `sandbox.checks` lists, under "The Required checks", and a live session reads them from the Kit config in its checkout; both read `.github/workflows/` for what each runs. A test no Required check runs is moved where one does or dropped, and a workflow change to bring it in becomes an Operator step that blocks the Ticket. The Glossary gains **Acceptance criterion**.
- An Implementer that finds an acceptance criterion no run can meet no longer commits nothing. `prompts/implement.md` names what makes one: a Trust-root change, a GitHub write, a commit, branch or state the run wasn't given, a suite or command no Required check runs, something only the Operator can do, or a literal no output can satisfy. The run builds the rest of the Ticket, commits it, and names each such criterion, quoted, with the reason, in its summary under **Criteria no run can meet**, so the pull request opens, its Required checks run, and it is Reviewed as any is. It never works around one: no Trust-root edit, no `gh` or API call, no result claimed for a command it didn't run. A Ticket with nothing buildable without one still ends in no commits, with the reason in the summary. The rule holds on a first run, a Kept-branch start, a Retry, a Touch-up and a Request-changes run, and on a run on a pull request the heading stays in its body while the criterion is unmet. "Questions for the Operator" stays the one heading for questions. The Kit does nothing with the new heading ([#764](https://github.com/jrey8343/fabrik/issues/764)).
- **The Design session's default effort is `high`** ([#767](https://github.com/jrey8343/fabrik/issues/767)). A miss in a Design session costs a Back to design, the sessions are the cheapest runs in the factory ($41 of the $404 spent from 7 to 15 Nov), and the longest turn took 4.1 of its 30 minutes ([#722](https://github.com/jrey8343/fabrik/issues/722)). A Replay can't vary Design, so this goes in without one. A repo's own `roles.design.effort` still wins, and a `null` or missing one takes the default, now `high`. A prototype turn runs on the Design role's model and effort, so it runs at `high` too, within the Implement role's time limit. Every other default stays: `high` for the Review, `medium` for Triage, Implement, the Auditor, the Retro, the Researcher, the Digest writer and the Step-up, and the Design time limit stays 30 minutes. The starter Kit config names `high` for `roles.design`.

## Upgrading

<!-- Written by the Tickets whose change asks anything of a Product repo beyond merging the bump. -->

**Design at `high`** ([#767](https://github.com/jrey8343/fabrik/issues/767)). A Product repo that names no `roles.design.effort`, or names `null`, as gradually-core and Penrith do, takes `high` with the bump alone. One that names `roles.design.effort` outright, as a `.fabrik/config.json` written from an earlier starter does with `"medium"`, keeps that level until its Operator deletes the field, to take the default, or changes it.
