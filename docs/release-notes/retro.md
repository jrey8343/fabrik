# Release notes: the Retro

The notes for the minor release that ships the Retro ([#151](https://github.com/jrey8343/fabrik/issues/151)). Paste them into the release's notes file (see [releasing.md](../releasing.md)), with its version and pins.

## What changed

- Once a week each Product repo with the `fabrik-runs` store gets a Retro. From 00:00 UTC on `retro.day` (Saturday by default), the scheduled tick opens a pending Retro, a `fabrik:retro` issue from the Fabrik App, when something is new since the last one: an agent PR merged or closed, or an escape filed. Its opening starts two new jobs in the Loop workflow. The **Retro evidence** job gathers the repo's Run records, score files and transcripts from the store and the Operator's feedback from GitHub into one evidence bundle. The **Retro** job (Opus 5.5, 45 minutes by default, `roles.retro`, plus `.fabrik/retro.md` when present) reads that bundle and a read-only checkout of the default branch with the Base skills alone. The README's Retro section has the whole of it.
- The Retro fills its issue with at most 3 proposals to change how the factory works in the repo, each with its evidence as links, the exact change, Mechanical or Judgement and Tighten or Loosen badges, and an **Open as issue** link: to the Product repo's form for its code (through Intake and Triage) or, with `ready-for-human` as an Operator brief, for its Trust-root files; to Fabrik's own form for a Kit change; or to an Extra skill's Skills source when the Operator owns it. The Kit checks every proposal against the bundle and drops what doesn't hold: a ref the bundle lacks, a one-off with no escape and fewer than two PRs, and a loosening without a streak of at least 20 clean PRs. A week with nothing to propose closes the Retro as clean.
- The Retro changes nothing in the repo: no branch, no PR, no state label, and no mention or assignee, so it never pushes to the Operator's phone. It surfaces in the Weekly summary instead, as each repo's open Retro in Waiting on you. A failed run, its evidence job's included, closes the Retro as not planned with one line saying why, and a later tick tries again, until two runs have failed that week. No new Retro opens while one is open or while the weekly-limit issue is open.
- The Retro evidence job runs no agent and no Product code, and reads `fabrik-runs` with a Contents-read token scoped to the one Product repo's paths. ADR-0009 has an addendum for it. A Retro run leaves a Run record in role `retro`, which counts in the Weekly summary's total cost but never per merged PR or per Spec; the evidence job leaves none.
- `CODING_STANDARDS.md`, an optional file at a Product repo's root, holds its coding standards. The Reviewer judges every PR against it when it's there, and the Retro proposes Judgement lessons as lines for it. It's a Trust-root file: an agent change to it is refused, and a Ticket touching it is never a Fast path. This part is live in every Product repo, with or without the store.
- New Kit config fields, each with a default: `retro.day` and `roles.retro`. No shim change, no new secret and no new App permission: the Fabrik App already has Contents on `fabrik-runs`, and the evidence job only narrows it to read. There's no setup step beyond the `fabrik-runs` store a repo already has, so a Product repo only merges the bump PR. `/fabrik-setup` now also creates the `fabrik:retro` label.

## It starts on taking the release

There's nothing to turn on: the Retro starts once a Product repo with the `fabrik-runs` store merges the bump PR, on its next `retro.day`. A repo without the store, or whose store isn't private, gets no Retro and no notice until the store is set up. To keep the Retro out of a repo, such as one you aren't developing, set `"retro": { "day": null }` in that repo's `.fabrik/config.json` before you merge the bump PR.

1. **Take it in the Pilot first.** Merge this release's bump PR in the Pilot only. To see a Retro before Saturday, set `retro.day` there to today's UTC day and set it back once the Retro has opened. The Pilot needs an agent PR merged or closed in the last 7 days for its first Retro to open. Then check:
   - an `issues.opened` event from the App's pending Retro starts the Loop workflow and routes through the Retro evidence job to the Retro job, and the pending Retro carries the `fabrik:retro` label;
   - the evidence job's step summary, which gives the bundle's size in characters and whether it was cut to fit: note it on [#228](https://github.com/jrey8343/fabrik/issues/228) against the 300,000-character budget, with how long the job's sparse checkout of the store took;
   - the Retro fills in, or closes as clean, with no mention or assignee, each card's evidence links open, and the next hourly tick opens no second Retro;
   - one Retro run's cost and duration, from its Run record in `fabrik-runs`, noted on [#228](https://github.com/jrey8343/fabrik/issues/228), to check the 45-minute default timeout.
2. Once the Pilot is healthy, merge the bump PR in the other Product repos.
