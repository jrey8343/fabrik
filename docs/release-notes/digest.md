# Release notes: The Digest

The notes for the release that ships the Digest ([#594](https://github.com/jrey8343/fabrik/issues/594), ADR-0022): the Kit's plain-English account of an agent pull request as it stands at one head, which a role of its own, the Digest writer, writes each time the pull request arrives at the Merge gate at a new head. Paste them into the release's notes file (see [releasing.md](../releasing.md)), with its version and pins.

## What changed

- **Every agent pull request gets a Digest before it reaches the Operator.** A Digest is an account of the pull request the Operator can decide from without reading its thread. It is a comment of its own, posted by the Fabrik App, written as of one head and never edited. The Digest writer writes it, never the Reviewer, so its first item can be that a pass was wrong. Kit code counts everything that can be counted and lays the comment out; the writer words it, and judges one thing: whether each thing the Operator asked for is in the head.
  - **The top has four sections**, in plain English with no code:
    - **Needs your eyes**: at most four items, or "Nothing." First anything the Operator asked for that is not in the head, then what only the Operator can judge, then what was not proven. Each item ends with links to the lines it is about, which the Digest points at and never quotes.
    - **What it does**: what changes for the End user.
    - **How it got here**: the rounds as counts, ending with whether the product code changed since the first Verdict.
    - **Follow-ups**: the Follow-ups the pull request's passes named, each with its "Open as issue" link, or "None named."
  - **Four folds sit under it**, each closed until opened:
    - **Walk me through it**: how the change works, and the order to read it in.
    - **Decided without you, and left alone**: what the Implementer decided that the Ticket did not settle, and what it left alone.
    - **The rounds**: Kit code's table of every round, with who, what and each Verdict's effect on the code.
    - **The criteria and how each was checked**: Kit code's table of every Request changes of the Operator's, each of its line comments and each of the Ticket's criteria, with whether it is in the head, how that was checked and where the writer looked.
- **The Merge gate opens a little later.** A pass no longer takes the pull request out of draft and requests the Operator's review at once. It adds `agent:digest`, the Digest writer runs, and when that attempt ends the Digest is posted, the pull request leaves draft and the review is requested. The Operator is told once, when the account is there.
  - **On the Actions tab** the run shows as "PR #<number> labeled agent:digest", since the caller workflow is unchanged, and its job is named "Digest PR #<number>".
  - **The wait**: in the trial a Digest took 20 to 75 seconds to write. Through the Kit there are two more jobs around it, the Kit job before and the push job after. The draft holds its `max_in_flight` slot meanwhile.
- **The Loop never waits on a Digest's success.** It waits for the attempt, which has 10 minutes by default. A run that fails, one that runs past its time limit and a reply Kit code refuses each open the gate all the same, under one comment that mentions nobody: "No Digest could be written for this head", the short head and how, which is `failed`, `timed-out`, or `refused` with Kit code's reason.
  - **Kit code refuses** a reply that leaves an ask of the Operator's unanswered, one whose items do not cover every ask missing from the head, and one whose top runs over 180 words. It also refuses one that breaks the reply's shape, one that names a Follow-up Kit code did not list, and a Digest too long for one comment.
  - **A wrong file or line refuses nothing.** That one link is dropped and the Digest lands.
- **A Digest run is never held** and never counts against a Ticket's Retries.
  - **With Subscription rotation on and every Subscription used up**, where any other run would be a Held run, the gate opens at once and the line says `no-subscription`.
  - **With no run started**, the gate opens at a Tick once the label has waited 30 minutes, and the line says `never-started`. The label is not added again and nothing is handed to the Operator. The usual cause is `main` moving just after the pass: GitHub starts no workflow for a pull request that conflicts with its base.
- **Carried forward and collapsed.** When a pull request comes back to the Merge gate at a new head and only `main` moved under it, the last Digest is posted again for the new head and no model runs. That is when the pull request's own change is the same, by the fingerprint below, and the Operator has requested no changes since. The carried Digest has one added line, "Carried over from" the head it was written at, "because only `main` moved." Its links follow their lines to where they now sit, and a link whose lines cannot be found is dropped. Each time a Digest is posted, the older Digests on the pull request are collapsed as outdated.
- **Every Verdict carries a fingerprint** of the pull request's own change, as a hidden line under the Verdict's marker: the lines it adds and removes against its merge base with the default branch, so a rebase onto a moved `main` leaves it equal. From it Kit code works out whether the product code changed since the first Verdict, each Verdict's effect on the code in the rounds table, and whether a Digest can be carried forward. A pull request whose first Verdict predates the release has no fingerprint there, so its Digest says the comparison "could not be established".
- **A Request changes on a passed draft** waiting on its Digest is acted on at once, as one at the Merge gate is: its Request-changes run starts, the pull request stays in draft, `agent:digest` comes off, and the Digest being written is thrown away. The pass on that run's push brings the next Digest. Send it back closes such a draft as it does any agent pull request. A Request changes on any other draft does what it did before.
- **No agent run is given a Digest,** and nothing in the Loop moves because of what one says. A Digest and a no-Digest line are left out of every agent's input, the Digest writer's own included, and the Retro's evidence leaves out a Digest run's Run record with its transcript. When a Digest says something the Operator asked for is not in the head, it is the Operator's Request changes that acts on it.
- **Kit config:** two additions, each with a default, so no Kit config edit is needed.
  - `roles.digest` sets the Digest writer's `model`, `effort` and `timeout_minutes`. Left out, its model and effort are the repo's own `roles.review`, whatever that is set to, and its time limit is 10 minutes. The Digest writer takes no Extra skills. A repo's own instructions for it go in `.fabrik/digest.md`.
  - `digest.enabled` is the Digest's switch, `true` by default.
  - **To turn it off** in a Product repo, set `digest.enabled` to `false`. A pass then opens the Merge gate itself, as before this release, and `agent:digest` is declined with one line saying so.
- **The label:** `agent:digest`, which the Operator may add to an agent pull request with a pass on its current head to have a Digest written. On one already at the Merge gate a fresh Digest is posted and nothing else moves. Anywhere else the label comes off with one line saying why. GitHub makes the label the first time the Kit adds it, plain, with no colour or description of the Kit's. Setup creates only a label that is missing, so it colours and describes this one only in a repo where it runs before the first pass.
- **Spend:** a Digest run has a Run record in its own role, `digest`, on its Ticket, and its cost counts toward the Weekly summary's cost per merged pull request, and its spend that never merged, beside the Ticket's Implement and Review runs. The Run-record schema is as it was. A Digest carried forward costs nothing. In the trial a Digest cost $0.11 to $0.47, which is a trial's figure, measured on a laptop and not through the Kit. No Scorer judges a Digest yet.
- **For a reader of the Kit:** the read library's row for each open agent pull request carries its Digest as data: each item's kind, claim, sentence, places, picture and suggested request, the two texts and the Follow-ups, with the folds as Markdown. In place of it a row says that the Digest is not readable (edited by hand, written at a version the library does not know, or malformed), that none was written and how, or that there is none. One more read, `readDigestPlaces`, made for one pull request when a screen opens, gives each place's real lines from the head, checked against the place's fingerprint: code inside the diff as its diff hunk, code outside it and words as plain lines. A reader never parses a hidden line or the Markdown. A Digest run in flight is in the runs read, in role `digest`.
- **The Standing** of a passed draft waiting on its Digest is at Review and is the Kit's move: "The Reviewer passed #12, and the Digest writer is writing its Digest. The Merge gate opens when it ends, with a Digest or without." It turns Stuck only if the gate never opens. There is no new Standing name.
- **A word changed:** "digest" in the Kit now means only this. What the Kit's code and README called by that word before, a finished run's transcript cut down to fit a budget, which the Scorers' judge and the Retro read, is the trimmed transcript. One stored score-file field keeps its old name, so no score file and no store changes for it.
