# Release notes: a bump says it took

The notes for the minor release that has the Tick confirm a newly pinned release is running ([#548](https://github.com/jrey8343/fabrik/issues/548)). Paste them into the release's notes file (see [releasing.md](../releasing.md)), with its version and pins.

## What changed

- **The first Tick on a new release says so on the PR that pinned it.** Every hourly Tick finds the newest commit on `main` that changed the release `.github/workflows/fabrik.yml` pins, and the merged pull request it came from: a Kit bump, Setup's PR, your own PR or a revert. If the Fabrik App hasn't already said so there, it comments "Fabrik vX is running here", with the time the Tick started on it in your time zone, a link to that run, and a link to vX's release notes. After you merge a Kit bump, that comment within the hour means the release took. No comment within an hour or two means the Tick isn't starting: look at the Actions tab for `fabrik.yml`. The daily Tick check opens a Dead-tick issue after a day.
- It comments once per release on each PR. A hidden marker in the App's comment, naming the release, is how it knows. No store or file keeps track. When two pin moves land before one Tick, only the newer one's PR gets the comment. A revert is just another pin move, so the revert PR gets "Fabrik v<older> is running here". A pin moved by a direct push to `main`, or a caller that pins no exact release, gets no comment. The comment @-mentions nobody.
- It runs in a new job of the scheduled tick, Release running, which mints its own Fabrik App token and holds no `GITHUB_TOKEN` permission. It can't fail the Tick. If GitHub refuses a read or the comment, or the App token can't be minted, its step summary says why in one line, and the next Tick tries again.
- **Why a minor:** this is new behaviour with no change for a Product repo to make. The caller workflow's permissions, the shims, the Kit config and the App's permissions are as they were (it comments on pull requests with the Pull requests write the App already has). A Product repo only merges the bump PR, and that PR is the first to get the comment.
