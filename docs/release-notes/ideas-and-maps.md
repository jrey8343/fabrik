# Release notes: Ideas and Maps

The notes for the minor release that ships Ideas and Maps in the Loop ([#154](https://github.com/jrey8343/fabrik/issues/154)). Paste them into the release's notes file (see [releasing.md](../releasing.md)), with its version and pins.

## What changed

- **A Design session can chart a foggy idea as a Map.** Capture stays a blank issue. An idea too foggy for one Design session fails Triage's Fast path on size, goes to `needs-design` as usual, and Triage's comment adds one line: `This looks too foggy for one Design session.` When that line is there, or the session judges the destination can't be designed in one session itself, round 1 asks "Chart this as a Map instead?" with a recommendation. A no keeps the session designing, and any later round can still end in a Map when the Operator asks for one. A Ticket under a Spec never becomes a Map. The README's Maps section has the whole of it.
- **The `map` outcome**, a sixth Design-session outcome, rewrites the issue in place as the Map: Destination, Notes, an empty Decisions so far, Not yet specified and Out of scope, carrying its `From audit`, escape and `From retro` lines. Its first Decisions are filed as its sub-issues, blockers first, each with its `wayfinder:research`, `wayfinder:prototype`, `wayfinder:grilling` or `wayfinder:task` label, native blocked-by edges and no state label, so Intake leaves them alone. `needs-design` is swapped for `wayfinder:map`, the issue keeps its category label, the closing comment lists the Decisions (no mention), and the Kit runs a Dispatch check and a Design queue check. `/fabrik-live-design` gains the same ending: it checks the Map cap before offering a Map, rewrites the body, files the Decisions with `gh`, and only then posts a comment starting `<!-- fabrik:live-outcome map -->`, on which the Kit swaps the labels.
- **Research Decisions run AFK.** Dispatch adds the new trigger label `agent:research` to each open research Decision on an open Map that nobody is assigned to, no open issue blocks and whose last run didn't fail, and the claim job takes it off as the run starts. Research runs share `max_in_flight` with Implement runs: Tickets and research Decisions are released together, lowest issue number first, and `max_in_flight: 0` pauses both. The new **Research** job (Opus 5.5, 30 minutes by default, `roles.research`, plus `.fabrik/research.md` when present) is read-only like the Audit job: a checkout of the default branch, only the agent service account, no GitHub credential and no production secrets, and the Base skills alone. The Researcher follows the pinned `research` skill and writes one findings file, `docs/research/<number>-<slug>.md`, on a throwaway `research/<number>-<slug>` branch, deciding nothing.
- **The push job lands the findings.** When the branch changes only its findings file, it pushes the branch (never merged, no PR), posts a resolution comment on the Decision with the gist, the key facts and a link to the file, closes the Decision as completed, appends one line to the Map's Decisions so far (re-reading the Map's body right before it writes, so the Operator's edits stay), and runs a Dispatch check. A branch that changes any other path is refused with nothing pushed. A failed research run posts the usual failure notice on the Decision, and Dispatch leaves the Decision alone until the Operator re-adds `agent:research`. Every research run leaves a Run record in role `research`; no Scorer samples it.
- **The Map cap.** `caps.maps` (default 1, only-tighten, `0` stops new Maps) caps the open `wayfinder:map` issues in a Product repo, one charted by hand included. It holds silently. While it's full, a Design session offers no Map, and a `map` outcome that lands anyway is refused with a comment naming the open Map, the session carrying on.
- **Reaching the destination** is a documented `/wayfinder` convention, not Kit code: the Map's last Decision files each Spec-to-be as a new `needs-design` issue linking the Decisions it rests on, the Design session treats them as settled, and the Operator closes the Map. Spec closing never closes a Map.
- **The Weekly summary** lists each open Map in Waiting on you with how many of its grilling, prototype and task Decisions wait on the Operator, and each research Decision whose last run failed. Held shows the Map cap when it's full, naming the open Map.
- New Kit config fields, each with a default: `roles.research` and `caps.maps`. No shim change, no new secret, no new App permission and no setup step: the Fabrik App already pushes branches and writes issues, sub-issues and their dependencies, and GitHub creates the new labels on first use. So a Product repo only merges the bump PR. `/fabrik-setup` now also creates `wayfinder:map`, the four `wayfinder:<type>` labels and `agent:research`.

## It starts on taking the release

There's nothing to turn on: Maps and research Decisions start once a Product repo merges the bump PR. To keep new Maps out of a repo, set `"caps": { "maps": 0 }` in its `.fabrik/config.json` before you merge the bump PR.

1. **Take it in the Pilot first.** Merge this release's bump PR in the Pilot only. Then open a foggy idea there as a blank issue, and check:
   - Triage sends it to `needs-design`, and its comment carries the fog line;
   - round 1 of its Design session asks "Chart this as a Map instead?" with a recommendation, and a yes lands the Map: the body in the Map shape, `wayfinder:map` in place of `needs-design`, and the Decisions as its sub-issues with their `wayfinder:<type>` labels and blocked-by edges;
   - Dispatch adds `agent:research` to an unblocked research Decision, the claim job takes it off as the Research job starts, and its findings land: the `research/<number>-<slug>` branch pushed, the resolution comment on the Decision, the Decision closed, and its line at the end of the Map's Decisions so far;
   - one research run's cost and duration, from its Run record in `fabrik-runs`, noted on [#263](https://github.com/jrey8343/fabrik/issues/263), to check the 30-minute default timeout;
   - the Monday Weekly summary lists the Map in Waiting on you and names it under Held.

   To check the live ending too, close that Map once its research has landed, so the cap has room again, then end a `/fabrik-live-design` session on another foggy issue in a Map, and check the Kit swaps `needs-design` for `wayfinder:map` on its marker comment.
2. Once the Pilot is healthy, merge the bump PR in the other Product repos.
