# An Operator session runs in a Claude Code cloud session, started by a link, and the Console draws no chat

An Operator session has to run with no machine of the Operator's on, on one of their Subscriptions, on the model and effort they choose, and be talked to from a phone. It runs in a Claude Code cloud session: a throwaway VM of Anthropic's, with the conversation in Claude's own app. The Console starts one with a `claude.ai/code` link that names the issue's repo, the first prompt and a Session environment, a cloud environment kept for Operator sessions alone. The Operator picks the model and the effort on Claude's form and sends. A trial on the Operator's phone (#808) found this works as a place to pair: a prompt is answered in the app, and a push arrives when the session needs the Operator.

- **One host serves both kinds of work,** a Pairing session and a Map's HITL Decision.
- **Power is brought to the conversation.** What a cloud session can't reach is reached from it, by a connector, a dispatched workflow that holds its own credential, or a credential attached outside the VM. The conversation never moves to a second host. The posture's ADR says which of them a repo may use, and in what order.
- **A session is disposable.** An idle VM is paused, and a session picked up after a night was where it was left, on the same disk under a new boot, with nothing that had been running still running (#873). A reclaim was never seen and the docs promise nothing against one, so nothing that matters lives only in a session: its work is pushed and written on its issue as it happens, and a later session picks up from the issue and the branch.
- **A Pairing session in the Operator's own terminal stays as it is,** for the steps no Operator session can do: those bound to that terminal, and those only the Operator's hands can do.
- **No fallback is built.** If Anthropic changes or withdraws cloud sessions, the terminal's Pairing session still works and this is decided again.

## Considered options

- **One Actions job per turn, with the chat drawn by the Console.** It runs on the token the Kit's jobs already hold. The Console would grow a chat screen and a stored conversation, every turn would wait on a runner starting, and the app's prompts, pushes and model picker would all have to be rebuilt.
- **Remote Control on an Actions runner.** The Kit's token can only make model requests. Remote Control needs the Operator's whole Claude sign-in, kept in CI and written back after every job, by a path nobody has proven and Anthropic's terms don't clearly cover. The conversation would die with the job at six hours.
- **An always-on box of the Operator's.** ADR-0002 already rules one out, for HITL sessions too.
- **A scheduled task's `/fire` in place of the link.** It starts a session with no tap in Claude's app and returns the session's URL. Its repos, model and effort are fixed when the task is saved, so there would be a task per repo and the choice of model would be made by typing once inside. Its prompt reaches the session labelled as untrusted data, the Console would hold a bearer token per task, and it is a research preview.

## Consequences

- **The Console hears nothing back from a hand-off:** no session URL and no state. A session reports itself on its issue: in a cloud session the Kit's SessionStart hook works out the session's address from `CLAUDE_CODE_REMOTE_SESSION_ID`, and the session writes it in a marker comment as its first comment there, which the Kit reads and the Console draws as the row's way back to the session (#812). A session that writes nothing there is invisible to the Console.
- **On an iPhone the link opens in Safari, by Safari's own scheme.** The Claude app ignores a new session's repo and prompt, and `x-safari-https:` was the one way of nine tried that arrived with the form filled in (#806). It is not a scheme Apple documents. A live session's plain link opens in the Claude app, on that session. A link lands on whichever Claude account the browser is signed in to, and Safari holds one sign-in at a time.
- **The Kit's SessionStart hook is the one way skills reach a session there,** as at the terminal (ADR-0003, ADR-0008). A cloud session refuses an archive of a repo that isn't attached and serves git's own reads of a public one, so the hook fetches Fabrik and each Skills source by a shallow git fetch from `github.com` (ADR-0003's addendum). It runs when the session starts and not again: a session picked up after a night did not run it a second time, so what it installed and said the first time has to be enough.
- **A session opens on one repo, and can attach another by itself.** While it has one repo it keeps that repo's hooks, settings and `.mcp.json`. It can attach a second repo the Claude GitHub App is installed on, with push, unasked, and carry on in the same VM (#809, #873). Picked up after a night with a second repo attached, it comes back as a session of both: the first repo's hooks no longer run, and the second repo's `CLAUDE.md` and skills load. A session started on several repos reads no repo's hooks. The posture's ADR says what a session may do in a second repo.
- **GitHub is reached over REST and through the GitHub MCP server, on attached repos alone.** GraphQL is refused, so `gh issue` and `gh pr` fail, and the Kit carries a REST form of each tracker write in its skill for cloud sessions, `fabrik-operator-session`, which `/fabrik-pair` and the working of a Decision use there. Actions runs, their logs, a re-run and a dispatch all pass. The proxy refuses a repo's secrets, variables, environments, webhooks, Actions permissions and branch protection, and a GitHub token handed to a session opens none of them: the proxy answers with the session's own credential in its place (#809).
- **A session runs in Accept edits, Plan or Auto.** There is no mode that asks before every act.
- **The Session environments are configuration on each Subscription the Operator opens sessions from,** made by hand from the README's checklist under the same names, and in no repo. The link names one by its name: `operator-sessions` for the bare one, or the one a repo's Kit config names as `console.session_environment`. Claude's form falls back without a word to the last-used environment when a link's name matches nothing, so each holds its own name in `FABRIK_SESSION_ENVIRONMENT`, which the hook compares with the name the repo expects. A session draws on its Subscription's weekly limit beside the Loop, and stays on the account it started on.
